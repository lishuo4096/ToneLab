# 验收记录（2026-11-10）

环境：Windows x64，MinGW-w64 GCC 16.1.0；设备 CH32V305 Audio Bridge V1.0，用户已将模拟输出接回输入。

## 设备信息与格式

`tonelab-cli inspect --backend wasapi --device 0` 读到 Windows 默认格式为 **96000 Hz / PCM24**。

驱动接受的双声道独占组合为 **48000 / 96000 / 192000 / 384000 Hz × PCM16 / PCM24 / PCM32**。本机该设备的 44.1 kHz 系列、float32 和 24-in-32 探测未通过，不会显示在界面列表中。

不指定 `--rate` / `--format` 的 CLI 播放已验证以 96000 Hz / PCM24 打开，不再沿用固定的初始位深。显式 384000 Hz / PCM32 直接生成并由独占流输出。

端点音量：20%，未静音，`QueryHardwareSupport` 报告硬件音量支持。通过脚本设为 19% 后读回 19%，最后恢复 20%。此项改变设备全局硬件音量，不更改左右生成器幅度。

## 物理回环

执行 `dist/loopback-test.exe 384000` 与 `dist/loopback-test.exe 48000`。输出、采集均为独占双声道 PCM32；左声道 997 Hz、右声道 2003 Hz，数字输出峰值均 0.05 FS。每阶段 0.8 秒，丢弃切换瞬态附近的数据，再计算回采 RMS 和目标频点相关幅度。

四阶段：双声道开启、左关闭/右开启、双关闭、左重新开启/右关闭。两档采样率的所有阶段均通过，两档均未报告输出欠载或采集不连续。

| 采样率 | 双开左 RMS | 双开右 RMS | 双关左 RMS | 双关右 RMS |
|---|---:|---:|---:|---:|
| 384 kHz | 0.00113991 | 0.00115670 | 0.0000679432 | 0.0000673548 |
| 48 kHz | 0.00114119 | 0.00115247 | 0.00000608497 | 0.00000600242 |

双开时各声道自己的目标频点幅度显著高于另一声道的频点，关闭后目标音消失。模拟 ADC 回采保留底噪，不应期待其为数字全 0。数字输出全 0 由下述逐字节测试另外验证。

完整测量值：`loopback-384000-wasapi.json`、`loopback-48000-wasapi.json`。这些测量验证了实际录放和开关行为，不是 DAC 模拟有效位数的测量。

## ASIO4ALL

已验证原生 PCM32、48 kHz 和 96 kHz 的播放启动/停止，3 秒测试均正常退出、欠载 0。宿主读取原生输出类型并请求采样率；驱动重置由所属 STA 控制线程合并并恢复，避免重复回调并发关闭流。

本次 ASIO 验证针对流启动及生命周期；ASIO4ALL 内部路由由其面板决定，不把 WASAPI 的 CH32V305 回环结果当成 ASIO 硬件回环结果。未通过自动化打开 ASIO 面板，避免打断用户桌面；按钮已接入 `ASIOControlPanel`，可由用户点击。

系统另有不可加载的 SXW、未连接的 TI ASIO 驱动，其枚举警告会写入 CLI stderr；枚举仍可找到 ASIO4ALL。枚举和格式探测移到后台后，这些驱动的初始化等待不会阻塞 UI 线程。

## 数值与 CLI 验证

`dsp-tests.exe` 报告 6981 项计数检查通过，覆盖 44.1–768 kHz 原生相位、处理块连续性、独立频率、PCM32 低位精度、波形边界、奈奎斯特拒绝、24-in-32 左对齐，以及播放中关闭左右通道后的逐字节全 0。

`python tests/cli_tests.py` 通过：非法参数/退出码、384 kHz PCM16/24/32/float32 WAV 头与逐点样本、PCM32 非零低位、四种基本格式全 0 静音文件，以及 24-in-32 扩展 WAV。

快照见 `../assets/ui-wasapi.png`、`../assets/ui-asio.png`，对应计时 JSON 已保存于本目录。
